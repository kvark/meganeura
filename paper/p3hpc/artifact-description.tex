\section{Overview of Contributions and Artifacts}

\subsection{Paper's Main Contributions}
\begin{description}
\item[$C_1$] A numerically qualified Vulkan/Metal training and inference
comparison with compiled PyTorch on seven GPUs, including models up to 1.7B.
\item[$C_2$] Search selection and preparation measurements, with explicit
kernel-decision cache states and numerical-policy limitations.
\item[$C_3$] Additional qualification on three integrated GPUs and Quest~3S,
experimental MI300X Vulkan support, and an XR queue-sharing application.
\end{description}

\section{Artifact Identification}
\newartifact
\artrel
The source implements the compiler and paired collection. The sixteen
archives are the sole inputs to the final framework performance and coverage
results. Historical search ablations and the separately versioned application
are not substituted for missing final-cohort measurements.

\artexp
Offline replay regenerates eight TeX fragments, a CSV with all process medians
and paired-ratio ranges, and coverage/search summaries. It rechecks 277
desktop native receipts, 769 valid paired-phase receipts, and ten Android
full-tensor comparison receipts. All 330 core native cells qualify, as do
246 completed measured native cells including larger models; 226 have ratios.
The incomplete B570 360M campaign and all rejected references remain visible.
Android archives omit the raw NPZ tensors: replay verifies hashes and
comparison receipts, not the original elementwise arithmetic. Fresh runs
reproduce the procedure, not the exact timing noise or driver failures.

\arttime
Offline analysis takes minutes and needs no GPU. The recorded campaigns sum
to 15.16 device-hours; setup, downloads, and unarchived bring-up are excluded.
A fresh full collection needs access to all eleven devices. It is not
required to regenerate the paper's results.

\artin
\artinpart{Hardware}
A CPU and several GiB of temporary disk suffice for offline replay.
Performance devices are RTX~5070, RTX~3050, H100, RX~7900~XT, MI300X,
Arc~B570, and M3. Radeon~780M, Ryzen~9600X iGPU, RPL-U, and Quest~3S
supply qualification only. Device and driver identities are in the manifests.
MI300X needs the experimental Mesa and AMDGPU patches of
Section~\ref{sec:availability}; the Mesa source is public as a draft merge request.

\artinpart{Software}
The analyzer uses Python 3.12+ and a clean checkout of Inferena
\code{add19182e5479e3f7549894c524ac6691d3dc363}. It imports that checkout's
qualification routines, avoiding a separate implementation of numerical gates.
No PyTorch installation is needed for offline replay. Collection uses Python
3.13.13 and PyTorch 2.13.0 at \code{cf30153c4c131c8164ee7798e5022d810682e2cb}.
The lockfile pins Meganeura \code{c19cb1c}, Blade \code{4845d65}, and Naga
\code{13f582d}. Desktop paired protocol is v33; Android protocol is v15.

\artinpart{Datasets / Inputs}
The archives preserve manifests, samples, qualification reports, logs,
compiler/search receipts, and environment data. SHA-256 hashes in
\path{final-cohort.sha256} identify the exact sixteen inputs. Shared lockfile,
checkpoint, and text-corpus hashes agree across campaigns. SmolLM2 uses pinned
public checkpoints; the other workloads use deterministic synthetic weights.
Timed inputs are deterministic; PyTorch's untimed language-model training gate
uses 256 matched real-text SGD updates. The warmup diagnostic's summary and
protocol are separate inputs, not a new main-cohort condition.

\artinpart{Installation and Deployment}
For offline replay, unpack the archives and check out the exact Inferena
commit above. Follow the supplement README; no GPU setup or model download
is needed. For fresh measurements, use that checkout's \path{EXPERIMENT.md}
and platform setup scripts. Driver installation remains a separate
prerequisite. The experiment requires the recorded explicit backend settings,
not merely the newest available software.

\artcomp
Collection uses three fresh processes per measured condition, both profiles,
20 synchronized samples after at least five calls and ten seconds of warmup.
Correctness-only runs use one process and one sample; Android warmup is two
seconds. Native search uses 30 seconds per session, with persisted kernel
choices scoped to campaign/model/profile. First-session misses and later
warm decisions are reported separately, not labeled as controlled driver-cache
cold starts. PyTorch compilation has a separate supervised 120-second limit.
Timing excludes optimizer updates; FP16 scaling housekeeping remains included.
The original binary is hash-checked before and after desktop runs.

\artout
Run \path{final_cohort.py} with the archive directory, \code{--inferena}
pointing to the frozen checkout, \code{--check} pointing to the supplied
tables, and \code{--output} pointing to a new directory. It verifies archive
identity and invokes the frozen collector's validators before generating
results. The CSV retains each process median and the three paired ratios;
the headline statistic remains the ratio of median process times. No outliers
are removed, and correctness-only times never enter performance aggregates.
The historical \path{cohort.py} supplies only the plot layout, and
\path{search_ablation.py} belongs to an earlier study; neither replays this
collection.

Numerical rejection is not evidence of a vendor defect or a speed win.
Native single-step gradient fidelity and PyTorch's trajectory gate are
explicitly different. Offline changes to thresholds cannot reconstruct
kernels a new search might select; a tolerance study would require a separate,
versioned experiment for both engines. The artifact has not undergone
independent artifact evaluation.

\newartifact

\artrel
DinoVision exercises native checkpoint transfer and shared rendering/ML
resources on a physical headset, separately from the framework comparison.

\artexp
The retained outputs should reproduce the stated host/device error checks,
and the sweep records should reproduce the reported queue-sharing tradeoffs.
It is not a PyTorch comparison or an on-device training benchmark.

\arttime
Allow about 5--15 minutes to inspect the retained records. A new physical
run requires Android deployment and headset setup; allow 60--120 minutes
if the Android toolchain is already installed. These are estimates.

\artin

\artinpart{Hardware}
Offline inspection needs only a CPU. Physical reproduction requires a
Quest~3S, a development host and a GPU for decoder training.

\artinpart{Software}
The pinned DinoVision source contains the Rust dependency lockfile and
deployment instructions. Android and OpenXR tools are needed for physical
deployment. The archive records the measured application and device setup;
no Android framework comparison is claimed.

\artinpart{Datasets / Inputs}
The public evidence archive contains the fixed frame, parameters, output
checks, raw sweep samples, manifests and full-resolution media.

\artinpart{Installation and Deployment}
Follow the pinned source and archive instructions to build and install the
application. Offline analysis does not require the headset or a new build.

\artcomp
Train and save the decoder on the host, transfer its checkpoint, then run
the joined encoder/decoder on the headset's rendering context.
Check the fixed-frame host/device outputs before the live queue-sharing
sweep. Retained evidence allows these two checks to be inspected separately.

\artout
The output check measures numerical agreement, not image-quality superiority.
The sweep measures application submissions, eye updates and worker latency.
Its records support Section~\ref{sec:edge}; none enters the framework timing
tables or portability aggregate.
