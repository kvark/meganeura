## Executive assessment

The project has a coherent purpose: a compact native training/inference
compiler with one Vulkan/Metal execution path and practical graphics
integration. The strongest demonstrated advantage is useful portable
execution and selected small-shape wins, not blanket superiority to PyTorch.
The frozen GPU-reference set has 12/20 strict minimal-latency wins but only
5/19 valid training wins and a 1.78× median training-time ratio.

The implementation is more heuristic and more specialized than the old
roadmap implies. That is not inherently bad: useful algorithms must be
represented before a search can find them. The opportunity is a small,
state-safe, shape-aware search over reusable generators, particularly
convolution derivatives and Metal attention. The design should keep legality,
numerical permission and profitability distinct.

The largest immediate research risk was overstating the evidence: sampled
outputs were described as output L2 without naming sampling; gradient norms
can be mistaken for full gradients; default compiled PyTorch is not all of
its automatic modes; old roadmap claims survived precision rollbacks and a
stricter benchmark protocol. The revised docs and paper address these limits.

Memory aliasing pins gradients used after the compiled dispatch sequence by
optimizer/clip work. That is correct and should not be "optimized away" by
reasoning only about compiled-plan consumers. Conversely, a pinned buffer
need not be shared/host-visible. Those distinctions have already caused
historical bugs and belong in regression tests.

## Dependency audit and provenance

The initial ignored local lockfile resolved `crossbeam-epoch 0.9.18`,
`anyhow 1.0.102`, and `quinn-proto 0.11.14`. RustSec reported two vulnerabilities
plus seven informational warnings. Targeted compatible updates changed those
three local resolutions to `0.9.20`, `1.0.103`, and `0.11.15`, respectively.
The subsequent scan exits successfully with zero vulnerability entries and
six informational warnings; it is not a warning-free audit.
This does not change the frozen paper revisions or establish minimum versions
for downstream consumers: `Cargo.lock` is intentionally ignored in this
library repository.

`crossbeam-epoch` and `anyhow` are selected through egglog and related
dependencies. `cargo tree --all-features --target all -i quinn-proto` reports
no selected path; its lockfile presence must not be presented as an exposed
network service. No exploit or affected call-site reachability was proven.
[Crossbeam advisory](https://rustsec.org/advisories/RUSTSEC-2026-0204),
[anyhow advisory](https://rustsec.org/advisories/RUSTSEC-2026-0190)

The remaining concern is egglog's `im-rc → sized-chunks` chain, including a
panic-safety unsoundness advisory and unmaintained dependencies. Other
maintenance warnings concern `bitmaps`, `im-rc`, `number_prefix`, `paste`
and `sized-chunks`. Do not dismiss an informational unsoundness finding as
proof of safety. Upstream replacement or optionalizing experimental e-graph
support needs a deliberate follow-up; it was not smuggled into this audit as
a broad dependency redesign.

CI audits a freshly generated compatible resolution. Release applications
should retain their own lockfile and run the same check on the actual shipping
feature/target set. A passing advisory scan does not prove memory safety in
our unsafe host/GPU boundary or in driver code.

## Infrastructure priorities

The core compile/test feedback is fast enough to keep more invariants in
ordinary CPU CI. Add tests for complete candidate construction and cache
identity before expanding search. Keep real GPU validation distinct from
offline shader compilation: Naga acceptance cannot reproduce a vendor-driver
bug or establish numeric behavior on matrix units.

The current workflow contains a software-Vulkan latency job. This audit did
not run that job or launch remote CI. Hardware benchmark automation should
explicitly record device isolation and reject interfered runs rather than
publish unreliable timing. Dependencies are pinned jointly where Naga's
module type crosses the Blade boundary; update them together and run the
cross-backend qualification suite.

For research-object reproducibility, retain exact measured source and
configuration independently of evolving documentation. The archive packager
correctly requires a clean repository; keep that guard. Package a reviewed
clean commit after camera-ready changes, and retain
the distinction between self-replay and independent artifact evaluation.

## Recommended next work

First, finish the accepted paper using the frozen result set and the
[revision checklist](../paper/p3hpc/REVISION.md). No new benchmark is required
to make the present claims precise. In parallel with later paper work,
extend the implemented state-isolated scalar search to complete cooperative
candidates and implement logical transactional checkpoint restore. Once
hardware is available, qualify the new scalar tuner before whole-step
confirmation and profile-motivated convolution/attention changes.

The full experiment design and acceptance criteria are in the
[performance plan](study/performance-plan.md). The main strategic change is
to make safe measured selection an early infrastructure task, while resisting
an unbounded compiler rewrite or new per-model kernel inventory.
