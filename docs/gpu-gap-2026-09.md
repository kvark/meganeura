# NVIDIA and Intel gap investigation

September 21, 2026. Targeted engineering runs, not a new P3HPC cohort.
RTX 5070 (595.91.07) and Arc B570 (Mesa 26.0.3), on the same i5-12400F host.
The GPUs ran one at a time. No clock, governor, driver or memory-policy changes.

## What changed

The largest confirmed inference gain is in scalar attention. The old score
layout made neighboring lanes access distant shared-memory elements. Reordering
scores removes most shared-store conflicts. Staging V alongside K avoids
loading the same values separately for every query. Forward workgroup width,
key-tile size, elements per thread and lane layout are measured choices.
The device's shared-memory capacity bounds legal staging sizes.

Dense split-K is another complete-plan candidate. It uses the existing matrix
generator and a short row reduction, including fused residual additions. The
residual is included only in the first partition. Each candidate is allocated,
initialized, checked and timed as a whole; an isolated matrix speedup cannot
install a slower producer/reduction sequence. K staging depth matters as well
as partition count and output tile size.

The search tries the physical axes in an interleaved order before their joint
combinations, across the retained logical forms. A long list of attention or
matrix candidates must not hide submission chunking until the budget expires.
Small combinations of layout changes are tried first. This is bounded enumeration,
not exhaustive scheduling or a promise of monotonic performance.

Two extraction defects were fixed:

- Egglog values are sort-local. Integer node IDs were being mistaken for tensor
  e-classes with the same raw value and charged imaginary tensor traffic.
- Unfusing an already fused matrix/add creates an intermediate with no original
  node binding. It received a token cost instead of its known tensor size.
  Successive optimizer calls consequently alternated fused/unfused/fused in all
  three matrix orientations. They now remain fused.

Outlining now hashes constant bytes and compares their bits without formatting
large tensors. Initialized, input-free egglog rule databases are reused per
thread. A process-wide clone cache is unsafe with egglog 2.0: clones share
mutable table notifications, and concurrent searches can lose pending work.
An egglog-only reproducer fails with the shared cache and passes 800 searches
with independently initialized worker templates. These are integration costs
we can remove without replacing egglog or serializing callers.

## Measured checkpoint

Matched strict-f32 pairs use PyTorch 2.13.0 at source `cf30153c`, default
compilation and validated CUDA/XPU graph replay. Existing compiler caches were
retained; this is not a cold-start comparison.
Meganeura uses fresh command recording, a 60-second soft search budget per
session and the unchanged full-output/gradient construction checks. Held-out
step timings exclude readback; profiling is a separate measurement window.

| Whisper inference, ms | Earlier tuned native | Attention/layout changes | Matched PyTorch |
| --- | ---: | ---: | ---: |
| RTX 5070 | 8.942 | 5.642 | 3.334 |
| Arc B570 | 18.067 | 12.355 | 7.747 |

The later search-order/K-stage revision repeats Whisper at 5.640 and 12.248 ms.
Training remains about 30.8 and 101.3 ms: the forward gain does not resolve the
backward gap. On NVIDIA, the accelerated path takes 4.893 ms versus PyTorch's
2.666 ms. Its existing cooperative attention takes roughly as long as the
improved scalar attention; cooperative instructions alone do not ensure a win.

Nearby NVIDIA SmolVLA controls give 4.510 ms without the dense split search,
3.765 ms with fixed-depth splits, and 3.539 ms with the expanded staging search.
The last run selected an extracted form with eight partitions, 64x64 tiles and
K stage 16. These are individual search/run results, not confidence intervals
or proof that the selected graph form always wins. Minimum-shape and training
latency must be checked separately.

Intel SmolVLA changes from 8.284 to 6.158 ms when the search can choose K stage
8. Its minimum-shape latency changes from 3.576 to 2.795 ms, selecting four
submission chunks. These runs preserve every construction-time numerical gate.

The PyTorch SmolVLA adapter also needed a correctness fix: self-attention used
normalized Q but unnormalized K/V, unlike Meganeura. Corrected pairs pass the
outer comparison. Earlier pairs using that adapter are not a matched semantic
comparison, even when their sampled checks happened to pass.

## What Nsight says

Whisper's final 128-thread/16-key scalar layout raises whole-capture SM
throughput from 35.08% to 49.89%. DRAM throughput is only 3.64%; shared-store
conflict throughput falls from 4.04% to 0.020%. Attention and matrix products
each account for roughly 2.2-2.3 ms of instrumented GPU intervals.
These percentages are not latency fractions or isolated barrier costs.

The strict PyTorch profiles use f32 SIMT attention and matrix kernels. Missing
tensor-core instructions cannot by themselves explain this strict-mode gap.
SmolVLA's remaining native time is mostly matrix work and split reductions.
The earlier native Nsight Systems capture also records about 0.75 ms in
`step` and 3.01 ms waiting, on average, so CPU submission is not free either.
These traced intervals are not substituted for held-out benchmark timings.

A lane-transposed shared K/V prototype reduced shared-load conflict throughput
from 21.54% to 5.06% but made NVIDIA attention much slower. It was reverted.
Subgroup reductions and tilewise softmax rescaling also failed to give a
portable improvement. Optimizing a counter or counting barriers is not enough.

## Hardware that remains unused

Blade used to report only square cooperative tiles, hiding Intel's native
8x16x16 f16/f32 tile. The capability API now retains the supported dimensions.
Independent rectangular kernels pass full CPU-f64 output checks on both GPUs.
On Intel, one aligned 128x3072x576 NN product takes 88 us versus 180 us for the
best scalar control, while a 50x720x2048 product loses. Rectangular production
codegen and measured selection still need work; these probes are not installed
as a universal fast path.

Neither installed Vulkan driver advertises native f32-input KHR tiles. Narrowing
f32 to f16, including compensated variants, is not generally strict-f32 safe.
NVIDIA also advertises [`VK_NV_cooperative_matrix2`](https://docs.vulkan.org/features/latest/features/proposals/VK_NV_cooperative_matrix2.html),
whose larger scopes and flexible dimensions need backend/compiler work. The 5070 is not H100; access
to a named Hopper instruction should not be assumed from an API feature.

## Construction cost and next steps

CPU-only, five-run medians on CPU 0 reduce ResNet outlining from 345.3 to
26.9 ms and the measured optimization call from 415.2 to 104.4 ms. Whisper's
corresponding calls fall from 28.3 to 8.3 ms and 62.7 to 42.4 ms. Reusing the
rule database reduces a small graph's optimization from 1.48 to 0.53 ms.
These timings exclude driver compilation and GPU tuning.

In the model searches, graph preparation takes milliseconds; repeated session
construction, weight initialization and full-gradient qualification take
seconds. Inferena does not yet use the initializer's immutable-parameter-sharing
option. Sharing requires matching representation and effects, not just names.
Avoid weakening qualification to make a larger search look cheap.

The extraction estimate is logical tensor traffic, not HBM traffic or a roofline
model. Arithmetic, launch cost, cache reuse and occupancy are plausible ranking
features. They need calibration and held-out tests before becoming coefficients
in the extractor. For now, measured physical alternatives and corrected size
accounting are more defensible than invented device constants.

## Paired checkpoint, September 22

Held-out strict-f32 medians after the search-order work above. SmolVLA on the
5070 is engine `39f1943`; the other three rows are `cf3bffc`. PyTorch is
2.13.0 at `cf30153c`. These are single runs, not a cohort.

| 5070 strict step, ms | Meganeura | PyTorch |
| --- | ---: | ---: |
| SmolVLA inference / minimum / training | 3.7 / 1.6 / 12 | 2.2 / 1.0 / 5.4 |
| SmolLM2-135M prefill / 1-token / training | 9.2 / 1.9 / 33 | 6.1 / 1.6 / 16 |
| ResNet-50 inference / minimum / training | 5.0 / 3.5 / 30 | 6.6 / 3.6 / 15 |

Arc B570 SmolVLA, same strict contract, is 5.8 / 3.1 / 26 against PyTorch XPU
2.6 / 1.7 / 7.9. The result record names device 57868 (BMG G21). The harness
still prints the first discrete Vulkan id it discovers, which on this host is
the 5070, even when `MEGANEURA_DEVICE_ID` opens the Arc.

SmolVLA inference GPU time is 3.02 ms, of which matrix products are 2.14 ms.
The selected plan is split-K 8, 64-wide tiles, K stage 32, mostly
`MatMul[50x4096x720]` at about 5.7 TFLOP/s. Attention is 0.23 ms. ResNet's
matrix work is 0.06 ms, so its inference lead and its training gap are
convolution, not this matrix schedule. Neither installed driver advertises an
f32 cooperative tile (`cooperative_f32_shapes` is empty). Intel's only f16 tile
is 8×16×16. Strict mode records `f16_cooperative_matrix_permitted: false` and
zero cooperative dispatches, so that rectangular tile is visible and unused
here. It cannot explain the strict-f32 gap.

The training search is the scheduling hole. Its 60-second budget finished 24
of 64 programs, all single-axis. Two submission chunks won, 12.80 ms to 11.58
ms. Split-K 8 / tile 64 / stage 32 then reached 11.04 ms on one graph and lost
the 5% plus noise gate against the chunked incumbent. Those two axes were
never crossed. Inference did try K stage 16: about 2.68 ms against an
incumbent near 2.83 ms, also inside the gate, and the joint list was still
ahead of it.

The ordinary graph now measures the first split-K layouts crossed with the
first chunk count before other graphs repeat that cover. One later strict
SmolVLA pair on the 5070 passes the same comparison: 2.9 / 1.3 / 9.6 ms
against the same PyTorch 2.2 / 1.0 / 5.4. The earlier pair on this host was
3.7 / 1.6 / 12. Inference installed split-K 8, tile 64, K stage 8 and two
submission chunks. Its summed matrix GPU time stayed 2.12 ms against 2.14 ms,
so the held-out drop is the whole step: chunking overlaps that split plan.
Training installed split-K 8, tile 64, K stage 32 and two chunks. Its matrix
GPU time fell from 9.35 ms to 5.92 ms, and the backward products are split-K
rather than the small-tile plan. The search median was 9.67 ms against the
11.59 ms chunk-only incumbent. That training candidate was not in the earlier
24-program prefix. This is one pair, not a repeat, and PyTorch remains ahead.
